# 编码与文案规范（咦投票）

## 文案红线（用户可见文案，一票否决）

1. **催办走召唤语气**，禁止质问：✅「这场还缺个人搭把手」「周六的位置给你留着」；❌「还差你的那份」「就差你了」「大家都盯着你」
2. **不碰资金词汇**：界面不出现「支付/收款/到账/代收」——本产品无任何资金功能（PRD 决策 D5）
3. **永不惩罚**：无逾期红点、无扣分、无"你还没完成"句式；提醒频控同人 ≤1 条/日
4. **口语化**：按钮写动作不写系统术语（「我来」不写「认领任务」，「搞定了」不写「标记完成」）

## 技术约定

- 契约 SSOT：`api/openapi.yaml`，改接口先改契约
- 后端分层 controller → service → repository，DTO 与实体分离（包 com.yivote.backend）
- 小程序只用微信官方组件（不引第三方 UI 库）
- 信任三原则（所有协作交互过这三关）：实名见头像 / 可改不可逃 / 永不惩罚
- openGId 由前端分享票据解出后随请求传（群维度聚合键），后端不做群名获取
